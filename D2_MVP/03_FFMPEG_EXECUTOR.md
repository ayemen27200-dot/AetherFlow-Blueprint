# D2 — FFmpeg Executor Specification

## المبدأ
استخدم `-c copy` لتجنب إعادة الترميز عندما تكون الحاوية والـcodecs متوافقة. لا يمكن ضمان توفير مورد ثابت أو تطابق الجودة/المدة في كل ملف؛ يجب اختبار أنواع الإدخال المدعومة.

## أمر أساس تجريبي
```bash
ffmpeg -hide_banner -nostdin -i input.mp4 \
  -map 0 -c copy -f segment -segment_time 300 \
  -reset_timestamps 1 output_part_%03d.mp4
```

> هذا مثال توضيحي. يجب تحديد مسارات مطلقة ومتحقق منها، وتحديد timeout، وتنفيذ الأمر بقائمة arguments من Python دون `shell=True`. قد تفشل بعض الحاويات/المسارات الصوتية عند `-map 0` أو عند stream copy.

## القيود
- لا تستخدم إعادة الترميز مثل `-c:v libx264` ضمن MVP.
- لا تغيّر الدقة أو معدل الإطارات عمداً.
- القطع ليس دقيقاً دائماً على الثانية المطلوبة؛ تنسيق المقطع يعتمد على keyframes وطبيعة الحاوية.
- شغّل ffprobe أو تحقق موثوقاً من المدة قبل حساب نسبة التقدم.

## التقدم
الخيار الأفضل هو `-progress pipe:1 -nostats` لخرج آلة قابل للتحليل بدلاً من الاعتماد على تنسيق stderr البشري. عند استخدام السجل التقليدي يمكن تحليل `time=HH:MM:SS.xx`، مع تجاهل الأسطر غير الصالحة. أرسل تحديثاً عند كل زيادة 5%، وأبق القيمة ضمن 0–100.

## تصنيف الأخطاء
| الحالة | التصنيف | الإجراء |
|---|---|---|
| Exit code 0 | success | `completed` بعد التحقق من المخرجات |
| ملف غير موجود/غير مسموح | `INVALID_INPUT` | فشل دائم ورسالة آمنة |
| ملف تالف/codec غير مدعوم | `INVALID_INPUT` أو `TOOL_ERROR` وفق التشخيص | لا تكرر بلا نهاية |
| Exit code 137 | قد يكون OOM | سجّل السبب إن أمكن، ولا تفترض أنه OOM دائماً |
| SIGTERM / طلب إلغاء | cancelled | أوقف العملية الفرعية بأمان |
| timeout | TIMEOUT | أوقف المجموعة وسجّل التشخيص |

## الاختبارات
- fixture قصيرة معلومة (مثلاً 5 ثوانٍ) و`segment_sec=3`؛ قد لا تنتج مقطعين بالضبط إذا لم توجد keyframes ملائمة.
- تحقق أن الملفات الناتجة موجودة وقابلة للفك وأن مجموع المدة قريب من الأصل ضمن هامش موثق.
- اختبر مسار مفقود، ملف تالف، timeout، خروج غير صفري، ومجلد مخرجات غير قابل للكتابة.

## أهداف أداء مشروطة
| الإدخال | الهدف الأولي (زمن الجدار لمسار المنفّذ الكامل) |
|---|---:|
| 30 دقيقة | أقل من 15 ثانية |
| ساعتان | أقل من 60 ثانية |

هذه أهداف قياس وليست ضمانات عامة؛ سجّل codec وحجم الملف والقرص وموارد VPS عند التقييم.
زمن الجدار يقاس على مسار المنفّذ الكامل شاملاً فحص الفك الإلزامي للمدخل ولكل جزء مخرجات
(وليس أمر النسخ وحده). القياس قابل لإعادة الإنتاج عبر
`scripts/benchmark_long_media.sh` الذي يبني عيّنتي 30 دقيقة وساعتين بلا إعادة ترميز،
ويسجّل زمن النسخ وحده وزمن المسار الكامل ومواصفات الجهاز في `data/bench/RESULTS.md`.
نتائج أي بيئة غير VPS المستهدف تبين بيئتها صراحةً ولا تعتبر إثباتاً للهدف؛ انظر
`D2_MVP/07_G2_EVIDENCE_LEDGER.md` لآخر القياسات وحالة كل هدف.
