# تقرير إغلاق مانع G2: تشغيل Compose الفعلي وفجوة الأداء (Task017)

التاريخ: 2026-10-25
الفرع: `arena/940efcbe-aetherflow-blueprint` — PR #6 مفتوح، غير مدموج.
الرأس المرجعي: `5d75e92` (راجع السجل الحيّ `D2_MVP/07_G2_EVIDENCE_LEDGER.md` لأي تحديث لاحق).

هذا تقرير تحقق وليس إعلان اعتماد. كل نتيجة أدناه مرتبطة بأمر فعلي أو تشغيل CI
منشور؛ البنود غير المتحققة مدرجة صراحةً في القسم 5.

## 1. ما كان مطلوب إغلاقه

1. خدمة worker فعلية في Compose بنفس الصورة ونفس ملف SQLite ومجلد التخزين،
   مع بقاء Uvicorn غير منشور للعامة، بلا ادعاء نجاح قبل تشغيل حقيقي.
2. اختبارات قبول على تثبيت نظيف (صحة، queued→completed، فك ترميز، إعادة تشغيل،
   مدخل تالف، منع تسريب، عدم كشف المنفذ).
3. توحيد معياري الفيديو الطويل دون حذف أي شرط، وقياس فعلي، ومصفوفة قبول
   توضح تزويد العامل بالملف وفصل G2 عن D3، وتقرير داخل المستودع.
4. التزامات وروابط CI وأوامر فعلية ونتائجها ومصفوفة معيار←دليل←نتيجة.

## 2. الأوامر الفعلية ونتائجها

### 2.1 اختبارات الوحدة والبنية (الساندبوكس المحلي)

```bash
pytest -q          # 191 passed, 2 skipped (تخطّيان بيئيان: حارس CI وffprobe)
pytest tests/unit/test_compose_config.py -v   # 8/8 ناجحة
ruff check .       # All checks passed
bash -n scripts/verify_compose_stack.sh scripts/benchmark_long_media.sh
```

الاختباران المتخطّيان محليًا يعملان على رانر CI (ffmpeg/ffprobe مثبّتان عبر
apt)؛ مهمة `verify` خضراء بكل خطواتها في run 40150132081.

### 2.2 تشغيل Compose على رانر Docker حقيقي

```bash
bash scripts/verify_compose_stack.sh   # داخل مهمة compose-smoke على ubuntu-latest
```

النتيجة: run **40150132081** — المهمتان `verify` و`compose-smoke` ناجحتان،
وكل خطوات الفشل متخطاة (أي لم يحدث فشل). السكربت بلا `continue-on-error`
ويعمل بـ`set -euo pipefail`، فنجاحه يعني اجتياز الأقسام العشرة كلها:
config validation، عزل البيانات، بناء وتشغيل، صحة DB حية، queued→completed عبر
HTTP من داخل شبكة Compose، فك ترميز مستقل في حاوية العامل، تالف→INVALID_INPUT
بلا مخرجات جزئية، إعادة تشغيل العامل وإكمال مهمة لاحقة، فحص تسريب التوكن
والمسارات، وتأكيد عدم نشر منفذ 8000 على المضيف.

خمسة تشغيلات فاشلة سبقت النجاح وكشفت عيوبًا حقيقية وثّقت كاملة في القسم 8 من
سجل الأدلة: صلاحيات bind mount لـuid 1000، مسار `file_transfer_spec.yaml` في
تثبيت الـwheel (أُصلح بـ`resolve_transfer_spec` وأربع اختبارات)، وعيبان في
سكربت التحقق نفسه (مقارنة JSON بكلمة حالة، واقتباس زائد في حمولة JSON ردّ
عليه الـAPI بـ422 الصحيح). تعذّر تنزيل سجلات Azure الخام من ساندبوكس البناء
(مضيف محجوب)، فأُضيفت آلية تنشر تشخيص الفشل تعليقًا على PR بصلاحية مقتصرة.

### 2.3 قياس الأداء الفعلي (بيئة الساندبوكس، ليست VPS)

```bash
bash scripts/benchmark_long_media.sh
```

| العيّنة | المدة | الحجم (بايت) | الأجزاء | نسخ فقط (ث) | الجدار الكامل (ث) | السقف (ث) | النتيجة |
|---|---:|---:|---:|---:|---:|---:|---|
| 30 دقيقة | 1800ث | 26,272,411 | 6 | 0.90 | 34.51 | 15 | لم تتحقق |
| ساعتان | 7200ث | 105,085,411 | 24 | 4.04 | 135.48 | 60 | لم تتحقق |

مواصفات البيئة: نواتا Intel Xeon @2.60GHz، 4 GiB ذاكرة، FFmpeg 7.0.2-static.
العيّنتان مبنيّتان بدمج عينة الـ5 ثوانٍ بلا إعادة ترميز. التقسيم بنسخ الدفق
تحت السقفين بفارق كبير؛ التجاوز سببه فحص الفك الإلزامي للمدخل ولكل جزء على
نواتين. السقفان لم يُغلقا: الإغلاق يحتاج نفس السكربت على VPS المستهدف.

## 3. مصفوفة معيار ← دليل ← نتيجة (ملخّص)

| المعيار | الدليل | النتيجة |
|---|---|---|
| worker حقيقي متشارك نفس DB/التخزين | compose-smoke run 40150132081 + 8 اختبارات بنيوية | مُثبَت تشغيليًا |
| Uvicorn غير منشور للعامة | القسم 10 على `docker ps` الحي + اختبارات بنيوية | مُثبَت تشغيليًا |
| queued→completed وفك الترميز المستقل | نفس التشغيل، أقسام 5–6 | مُثبَت تشغيليًا |
| تالف → INVALID_INPUT بلا مخرجات جزئية | القسم 7 + اختبارات تكامل | مُثبَت تشغيليًا |
| ديمومة عبر إعادة تشغيل العامل | القسم 8 | مُثبَت تشغيليًا |
| لا تسريب توكن/مسارات | القسم 9 + اختبارات وحدوية | مُثبَت للمسارات المغطاة |
| شهادة TLS عامة | شهادة `tls internal` لـlocalhost فقط على الرانر | غير مُثبَت (يحتاج DNS) |
| أداء 30 دقيقة/ساعتين على VPS | قياس ساندبوكس فاشل السقفين؛ سكربت قابل لإعادة الإنتاج | غير مُثبَت |
| عقد الرفع opaque وفصل G2/D3 | `agent/upload_store.py` + القسم 1/5 من سجل الأدلة | مُثبَت تصميميًا واختباريًا |

## 5. بنود غير متحققة (لا اقتراح اعتماد G2 قبل إغلاقها أو توثيقها خارج البوابة)

1. قياسا VPS للفيديو الطويل (30 دقيقة <15ث، ساعتان <60ث) — غير متاح من بيئة
   البناء؛ السكربت والمصفوفة جاهزان والنتيجة تملأ بقياس VPS حقيقي.
2. شهادة Let's Encrypt عامة على مضيف نظيف مع DNS ومنافذ 80/443.
3. تدقيق تسريب أسرار شامل لكل المكونات (المغطى آليًا حاليًا: مسار فشل العامل
   وفحص التوكن في سجلات الحاويات).
4. بنود D3 المؤجلة موثقة في القسم 5 من سجل الأدلة ولا تُحسب على G2.

## 6. الحالة

مانع تشغيل G2 الخاص بـCompose أُغلق بدليل رانر حقيقي منشور. معيار الإغلاق
الكامل لم يتحقق بعد: تبقى أدلة VPS للأداء، وشهادة TLS عامة، والتدقيق الشامل
للأسرار. PR #6 يبقى مفتوحًا وغير مدموج بانتظار قرار المراجعة المستقلة.
