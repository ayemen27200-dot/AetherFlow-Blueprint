# رسالة تسليم D5 للوكيل

نفّذ `D5_HARDENING` بعد اعتماد G4.

## اقرأ
1. D0 README وARCHITECTURE.
2. ملفات D5 من 01 إلى 06.
3. التقارير والـtests والقيود من D1–D4.

## المطلوب
1. إكمال test suite وقياس coverage ≥70%.
2. تنفيذ security review مع توثيق النطاق والأدوات والنتائج.
3. إجراء accessibility review آلي ويدوي.
4. تنفيذ backup/restore وتجربتهما على staging.
5. إعداد CI/CD وتثبيت إصدارات الأدوات وأفعال GitHub.
6. إكمال release checklist وعدم إنشاء tag قبل اعتماد النتائج.

## قواعد صارمة
- لا تعتبر قائمة التحقق تدقيقاً ناجحاً بحد ذاتها.
- لا تُخفِ فشلاً بزيادة exclusions في coverage.
- لا تطلق إصداراً مع findings حرجة غير معالجة أو استثناء موثق ومعتمد.
- لا تحفظ أسراراً أو ملفات وسائط خاصة في artifact.

## G5
ارفق تقارير الاختبار والأمن والإتاحة والاستعادة. إذا اكتملت البوابات فعلياً، اقترح release؛ وإلا وثّق المتبقي ولا تصف المشروع بأنه جاهز للإنتاج.
